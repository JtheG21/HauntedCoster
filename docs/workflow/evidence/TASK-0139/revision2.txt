Design as built
- ProfileRules.planSave(stored, op, now) -> (value | nil, alreadyApplied). nil when stored.version > 3 or the op has no valid identity
  (session id 1..64 chars, seq positive integer) or `now` is not finite. applied[op.sessionId].seq >= op.seq -> delta not added again,
  idempotent fields still overlaid. Otherwise delta added (cap 2^53) and applied[sessionId] = { seq, at = now }.
- sanitizeApplied: drops malformed entries, prunes at < now - 604800 (exactly 7 days kept), caps at 200 by oldest `at`; the op being
  written is never the one capped away (clock skew case).
- migrate: below v3 adds applied = {}; keeps unknown top-level fields and glyphsLifetime; a v3 log is not reset.
- overlay: known settings keys are written onto a clone of stored.settings (unknown sub-keys survive). `applied` is a map this build owns
  (pruned), so it is written whole; settings is the only record-type known field.
- Extra (found while implementing): adopt() now sanitizes, and toPatch()/toClient() copy the five known settings keys. Without this, an
  unknown stored settings sub-key would reach the session profile, make the strict sanitizeSettings reject every later settings patch,
  and be sent to the client. No remote payload change.
- ProfileService: sessionId = HttpService:GenerateGUID(false) per player session; the save op {seq, glyphsDelta} is taken without a
  yield and kept in `inflight` until a save succeeds; any error keeps the SAME op for the next attempt (leave loop, autosave,
  BindToClose, next debounced save); increments during the save wait in glyphsPending for the next seq; a successful retry chains a save
  for increments that waited behind it. Refused (version > 3): the op's delta goes back to pending, memory-only, warn.
- Studio-only hook: workspace attribute MathShowForceSaveErrorAfterCommit (ProfileService.forcedErrorAfterCommit). Inert unless
  RunService:IsStudio() and RunService:IsServer(); consumed once; errors after UpdateAsync committed. A client cannot set a server
  workspace attribute.
