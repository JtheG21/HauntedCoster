## Bypass checks

- **B1 Paths.** Exact case-sensitive directory prefixes include the slash. `06 QA-x/`, case variants, whitespace and Unicode lookalikes outside the literal prefixes remain disallowed. NUL splitting preserves spaces and line breaks. Standalone source deletes and mode changes are visible. Default rename detection hid the source path in a scratch commit moving `scripts/x.py` to `06 QA/x.py`. The gate saw only the destination. The three permitted trees accept arbitrary extensions and Git modes, including symlinks and gitlinks. Root `.gitattributes`, `.gitignore` and `.gitmodules` changes are outside the allowlist. The task-note exception is exact string equality with a mutable `note_path`, without a fixed directory or Markdown extension. A scratch-free code trace shows that a task can name a Luau file or script as the exception. The current workflow does not recurse into submodules.
- **B2 Record and X2 scratch reproduction.** A committed report said FAIL for the original measured SHA. Editing only JSON `audits[-1].result` to PASS made CI's gate return 0 and `approve_merge` accept with mocked GitHub metadata. After a further source edit correctly failed, updating only JSON `measured_sha` to that source commit restored exit 0 with the same report and hash. A separate scratch record with no report fields also passed. The gate re-hashes only if both fields are truthy and never parses the report at decision time. No real branch commits were made in these probes.
- **B3 Identity and X5 owner.** An executor named `claude-code` can supply `--auditor codex` with a matching report. No author, trailer, worktree or signature check authenticates the claim. The task JSON sets `owner_agent` and nothing pins that field to a trusted registration. CI does not compare it to auditor at all. `--by jg` and nonempty approval text are also caller-controlled.
- **B4 Ancestry.** Binding first requires measured to be an ancestor, then uses a two-tree diff. Main source changes introduced by merging main after measurement make the gate refuse, even when upstream already reviewed those changes. That is conservative for auditing the resulting tree. The chore source filter separately computes a merge base before comparing it to head. A three-dot diff from an already-verified ancestor would compare the same trees.
- **B5 Chore and light.** A plain chore branch touching games or scripts needs a matching task. Renaming to chore alone does not exempt a normal change there. A scratch rename out of scripts passed as a chore without a task. A matching JSON with `tier: light` also passed with source changes and no audit. The fast path ignores CI and policy files outside games and scripts.
- **B6 Workflow.** Uses pull_request, contents: read, no GH_TOKEN and no pull-requests permission because it uses Git only. Checks out the PR head at full depth. Untrusted refs enter through quoted environment variables. Missing or unparsable matching task JSON refuses for source PRs with no alternative matching record. Both actions use mutable tags. The head supplies the Python verifier and the workflow definition.
- **B7 Errors.** Missing gh, nonzero gh and syntax-invalid gh JSON refuse. Missing base/head or failed diff refuses in CI. Valid JSON with missing required PR fields can pass some checks. A light approval can store an empty head when the other metadata and checks look good. Deep and standard approvals reject missing heads through binding. CI skips draft and chore fast paths before task parsing by design.
- **X1 Status.** CI never reads status. Approve-merge and mark-merged require approved status at scripts/orchestrator.py:352,379. For deep and standard it is a prerequisite to binding, and cannot suffice by itself. For light, approval adds the check rollup (365–367) and marking adds the approval and GitHub merge metadata (380–398). Both skip audit binding. The override path (400–411) moves to done from changes_requested or blocked using a failed audit and caller-supplied strings, without GitHub verification.
- **X3 Standard.** scripts/audit_gate.py:115–125 requires a PASS and a nonempty auditor, but reserves the Codex identity check for deep. A non-Codex standard PASS qualifies, including one that the caller attributed to themselves via a JSON edit.
- **X4 Post-record expectation.** This audit's valid verdict is FAIL. scripts/audit_gate.py:117–118 deliberately rejects a recorded FAIL. A green post-record check would contradict the intended behavior. Recording also syncs the task note through scripts/orchestrator.py:203–228,257–263,320–324, which exceeds the two-file approval.
