## Evidence
- **Automated checks (re-run by the auditor):** `bash scripts/check.sh` passed stylua, selene, typecheck, `rojo build`, the 4 JSON files, orchestrator validate (10 tasks, 0 errors), `validate_vault.py` (0 errors, 0 warnings) and Python unittest (32 tests). Result: **ALL CHECKS PASSED**.
- **Luau specs:** I didn't re-run them (needs Studio). By reading: the 6 `TelemetryRules` specs test the pure functions `summarize`, `anonymize` and `buildSummary`, including a check that the encoded JSON contains no ids. Nothing tests `TelemetryService`'s record lifecycle.
- **Playtest ([[TEST-20261010-12]]):** 2 solo matches, both lines quoted verbatim. The numbers add up: totalS = courseS + finaleS + about 8.2 s of Results (`ResultsSeconds = 8`) in both matches. Both lines have `ended:"results"`. The note honestly lists what wasn't covered: a multi-player run, `ended:"empty"`, live serverErrors and rejections, and shrine opens.
- **Structural checks:**
  - **Nothing leaves the server.** No `AnalyticsService`, `HttpService:RequestAsync/PostAsync/GetAsync`, `MessagingService` or DataStore anywhere in `src`. `HttpService` is used only for `JSONEncode`.
  - **No new remotes.** No `RemoteEvent`, `RemoteFunction` or `OnServerEvent` added. Telemetry has no client input at all.
  - **Nothing runs per frame and nothing grows without limit.** Telemetry is event-driven: state changes, Echo add/spend and gate open/shrine. `summaries` is capped at 50 (`TelemetryService.luau:127-129`). Per-match tables are cleared on emit and on open. `rejectionBaseline` keeps a leaver's `Player` reference only until the match ends.
  - **Hook ordering.** `setState`, `EchoService.add/spend` and `ConvergenceGate.step` call listeners with `task.spawn`, which runs the listener at once until it yields. The telemetry listeners never yield, so each one runs inside the caller, after the state or attribute write it reports. `startMatch` fills `inMatch` before `setState("Course")`. `finale.results(...)` (which sets `lastOutcome`) runs before `setState("Results")`. `endMatch` runs before `setState("Lobby")`, and `emit` doesn't need the player list. A listener error stays inside its spawned thread, and `onMatchState` is wrapped in `pcall`. The new `FinaleService.results` code only computes and stores values; `LastResults` text is unchanged. **I found no change to existing behaviour or ordering**, which confirms the executor's claim.
  - **Lifecycle.** Course opens a record. Finale stamps courseS. Results fills finaleS, finishers and the outcome. Lobby emits. On the empty-match paths (Course→Lobby, Finale→Lobby), emit still runs with `ended:"empty"`, so a match where everyone left still produces a line. Countdown→Lobby never opens a record. A quick next match can't overlap, because emit runs synchronously on Lobby and a Countdown has to pass before the next Course.
  - **Privacy of the line.** `buildSummary` outputs only counts, aggregates, `P<n>` labels and faction strings. Factions are server-assigned from `FactionConfig.Active` (`FactionService.luau:95-98`). Echo power keys come from gate config through `GateRules.awardFor`. Neither can carry text a player chose. The `warn` paths print a Luau error message or a state name, not record contents. **I found no path from UserId, Name or DisplayName to the `[Telemetry]` line.**
  - **Pre-existing replicated attributes.** TASK-0008 only reads `FirstPowerSeconds` and `TrialEndReason` (replicated Player attributes from TASK-0006). It adds no new replicated attribute, so exposure doesn't get worse.
