## Previous findings status
| # | Status | Notes |
|---|---|---|
| F1 | fixed | The replicated `Player` attribute is gone. The counter is written to `ServerStorage.AbilityDiagnostics` as `Rejections_<UserId>`, and ServerStorage does not replicate. The folder is created in `start()` before the remote is created or parented, so `onRequest` cannot run while `diagnostics` is still nil. The `if diagnostics` guard is harmless. |
| F2 | fixed | `canUse` is wrapped in `pcall`. An error leads to `eligibility_error`, and any result other than `true` (including nil) leads to `not_eligible`. The closure type checks under `--!strict`. The "must not yield" rule is documented. If a `canUse` yields anyway, it cannot cause a cooldown double-fire, because `canActivate` and the commit still run with no yield between them. The cost would only be a stale `now`. |
| F3 | fixed | `MaxForce = AbilityConfig.Dash.MaxForce` (40000). The seated check runs after the cooldown check but before the cooldown commit, so a seated rejection does not use up the cooldown. That is correct. `allowSeated` is opt-in. Sufficiency: a default R15 character has a mass of about 15–20, so 40000 gives about 2000–2700 studs/s². That reaches 60 studs/s in about 0.03 s, well inside the 0.2 s window, and is about 12× the character's weight. On paper the force is ample. This was not confirmed at runtime (N1). |
| F4 | fixed | Added `0/0`, `true` and `Vector3` ids, each expecting `bad_type`. The optional note "checkRate counts rejected calls" was not added. That is acceptable, since it was optional. |
| F5 | fixed | The early return `player.Parent ~= Players` happens before `getState`, so no state is recreated after the player leaves. |
| F6 | not (deferred) | AC2 is still only partially met: no second-client view and no touch-button press. This is planned for the post-merge `AbilityProbe` scenario. |
