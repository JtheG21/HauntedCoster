## Revision changes checked
- **Tap mapping.** `InputObject.Position` for mouse and touch excludes the top-bar inset. `ViewportPointToRay` takes viewport coordinates. Adding `GetGuiInset().Y` is therefore correct (`TrackEditor.luau:470-472`).
  - The gamepad cursor stays in viewport space and goes to `onTap` unchanged (`:345`).
  - It's drawn at `(pos - inset) / UIScale` under a ScreenGui with the default `IgnoreGuiInset = false` (`:383-389`, `init.client.luau:18-26`), which is consistent.
  - The X inset is ignored. It's 0 on current clients.
- **Prompts.** `ProximityPromptService.Enabled = false` is set on open (`:459`). It's restored in `close()` (`:411`), which every exit path reaches:
  - Exit (`:566`), B (`:360`) and a successful Confirm (`:317`)
  - CharacterRemoving (`:569`), connected once because the gui has `ResetOnSpawn = false`
  - ride start (`init.client.luau:80`) and the HUD toggle (`:60`)

  Nothing else writes the property. A ride can't start while the editor is open (its prompt is disabled), and the server still refuses `SubmitRoute` during a ride (`TrainService.luau:552-555`).
- **Gamepad** (new): stick cursor, A tap, Y Move, X Delete, D-pad to cycle, Start to confirm, B to exit (`TrackEditor.luau:325-391`). It's bound at high priority with Sink and unbound on close (`:393-403`).
- **Clearance rule** (new): `TrackRules.luau:159-171` with `Track.MinClearance = 4`. It's O(m²) with m ≤ about 107 samples, run only after the length cap, so the cost is fine.
- **SubmitRoute** is unchanged and still solid (attempt-1 analysis holds): rate limit, server-side plot and tier gate, NaN and bounds checks, `n` capped before iteration, and re-validation after rounding (`TrainService.luau:540-580`).
