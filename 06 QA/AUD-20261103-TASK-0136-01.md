### F2 — major: the guard does not establish a clear 12-stud corridor
Location: tests/test_hub_routes.py:57-70,112-125.

Width is asserted from the sidecar's declared number, then only seven zero-width lanes are sampled, 2 studs apart at width 12, in 0.5-stud longitudinal steps. A collidable obstruction between lanes is invisible to both the width and rise checks. Segment endpoints can also be omitted when length is not a multiple of 0.5 (int(length/STEP)).

Reproduced using the actual Terrain/lanes/first_blocker functions, with no repository edits: a flat floor (centre (5,-0.5,0), size (30,1,20)), 12-wide corridor [(0,0),(10,0)], and a 4-stud-tall collidable block (centre (5,2,1), size (1,4,0.4)). All seven lanes return None/clear, while the solid at (5,1) reaches y=4 and narrows the corridor. Therefore these assertions do not implement the requested whole-corridor no-obstruction condition exactly. Passing real-map samples is useful but insufficient to certify the required continuous width.

Fix: test actual collidable footprints/body clearance across the full corridor, including segment boundaries/joins/endpoints and floor-transition events; enforce width >=12 and rise <=1.0 independently of merely declaring them in JSON. Add narrow-between-lanes and between-samples canaries. Do not change thresholds, tune constants to main, or fix this by merely increasing a finite sample density while claiming exact coverage.
