### Additional observations

- RateRules limits accepted requests/mutations and the configured thresholds are sensible, but both denied paths call push with a full QuestState for every rejected request. Source probe: 20 QuestRequest events cause 20 full state sends despite the 4/10-second allowance. Consider a separately bounded denial reply so the limiter also bounds response work; the committed suite does not test this behavior. QuestClaim's listener also ignores extra positional arguments rather than rejecting them as QuestRequest does. The parsed table itself is exact and cannot select another player's profile.
- QuestService:62 declares the entire exported table any. This does hide wrong method names/argument types from consumers; a green strict gate is not proof of that public boundary. The explicitly typed function bodies are still checked, and no concrete mismatched current call was found. Prefer a typed service/test-seam shape rather than disabling the whole exported API's checking. _test has no production/client reachability finding under the current server-only module placement.
- A loaded notification always pushes confirmed even if buffered commands were just queued; pending count remains available separately. Clarify that result versus pending semantics in T3. Pre-load facts during ProfileService's same-process rejoin wait can see persistence unavailable before a new session is installed and are dropped with a warning, rather than entering the loading buffer. This loss is not a retry/over-credit path.
