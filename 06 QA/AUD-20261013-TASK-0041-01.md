# Audit: TASK-0041 Interactive Haunted Trees (attempt 1)

## Verdict
**Pass with notes.** No blockers or majors.
- **Scheduler:** the `task.delay` token scheduler can't leak, double-run or leave a tree frozen forever. Each reschedule invalidates older delays, pending delays are bounded by `Remotes.allow`, and `resetAll` clears state on habitat deactivation.
- **Specs:** 140 passed headless (the auditor's own run).

## Findings
1. **Minor:** `HauntedTreeService.luau:97`. The rate limit is checked before the `looking == false` path, so releases and keepalives share one bucket (10/s, burst 20).
   - *Failure:* a player who drains the bucket, by sweeping fast across a cluster, has a release dropped, and the tree resumes after about 2.25 s (ttl plus delay) instead of 1 s. If a keepalive is dropped, the tree can resume for others while that player still looks.
   - **Open:** follow-up (a separate release bucket).
2. **Minor:** the scenario's wall and 20-stud checks are filtered on the client, so the server's facing and line-of-sight checks (`HauntedTreeService.luau:120-126`) are not exercised. The forged-report check only covers a tree more than 50 studs away.
   - *Failure:* a regression in the server's facing or line-of-sight check would still pass.
   - **Open:** follow-up (forge a near, blocked report). The AC7 line-of-sight claim rests on reading the code.
3. **Minor:** the scenario reads `Frozen` only on the server, not on each client.
   - *Failure:* a client replication or streaming fault would still score 20/20.
   - **Open:** follow-up. The AC6 evidence line already says both clients read the one replicated attribute; client-side reads were not taken.
4. **Minor:** `Woodland.luau:174-188, 221`. Placement clearance uses part centres with a 5-stud radius and ignores part extents (fallen logs up to 14 long, den mounds 10×8). Two Broad flares (about 2.7 radius each) can overlap.
   - *Failure:* a trunk clips a log end or a den, or two trees make a narrow pinch. `Reachability` passed 23/23, so a real trap is unlikely but not ruled out.
   - **Open:** follow-up.
5. **Nit:** the client checks line of sight from the camera; the server checks from the head.
   - *Failure:* the looker sees a local freeze while the server rejects the report and other players see the face move. Cosmetic.
   - **Open:** accepted as a known edge case.
6. **Nit:** the scenario's resume-after-cancel step has no upper bound. The 1.55 s in the TEST note is the 0.7 s hold plus 0.85 s until the 1 s delay expired from the new release, plus latency, so it is consistent.
   - **Open:** follow-up (add a bound).
7. **Nit:** ADR-0010 and the task plan described a "4 Hz sweep", a `HauntedFace` tag, a `Face` submodel, lower lids and a change to `Props.luau`, none of which shipped.
   - **Fixed** after the audit (documentation only; the code is unchanged from `b73c07a`).
