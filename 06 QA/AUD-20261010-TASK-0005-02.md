- **Luau specs:** I did not re-run them, because they only run in Studio. The executor claims 39/0.
- **F1 trace of `step()` plus `GateRules.cloneInput(present, consumed, seenAt, now)`.** The rule returns `(seenAt, false)` when the clone is absent, `(nil, true)` when it is present and consumed, and `(now, false)` when it is present and not consumed.
  - **(a) Clone at T, Ki at T+1, Ki again at T+5 with the same clone.**
    - From T: `seenAt` is refreshed every tick.
    - At T+1: `canOpen` succeeds. The opening sets `seenAt=nil` and `cloneConsumed=clonePresent=true`, clears `LastKiHit`, and holds the gate open until T+9.
    - From T+1.1: the clone is present and consumed, so the rule returns `(nil, true)` and Shinobi has no timestamp.
    - At T+5: the Ki hit sets `LastKiHit`. It is not evaluated while the gate is open.
    - At T+6: the clone expires, so the rule returns `(nil, false)`. `seenAt` stays nil.
    - At T+9: `canOpen` fails because Shinobi is missing, so the gate stays closed. The exploit from attempt 1 is closed.
    - The gate can reopen only if a new clone arrives while the T+5 Ki hit is still within its 10 s window. The clone cooldown is 8 s, so the earliest is about T+8. That opening uses two fresh applications, which is legitimate.
  - **(b) The clone leaves and a clone returns.** One tick with the clone absent resets `consumed` to false, and the next tick with a clone present sets `seenAt=now`, so it counts again. Clones are anchored and the plate uses an overlap box at 10 Hz, so a standing clone does not flicker in and out.
  - **(c) A clone is already on the plate when the gate is created.** The first `getState` has `consumed=false`, so the clone counts as having arrived at that moment. This is acceptable, because gates are built at map load.
  - **(d) Solo Ki opening while a clone is on the plate.** `cloneConsumed` becomes true. That can only happen with a leftover clone from a Shinobi player who left, since `required` contains Shinobi whenever a Shinobi player is present. The effect is conservative: the clone has to leave once. It does not matter in practice.
  - **(e) Opening while no clone is present** (the clone left inside the window). The opening sets `cloneConsumed=false` and `seenAt=nil`, so the clone time that was used is spent. Correct.
  - **Two Shinobi clones overlapping:** the second clone is not counted until the plate is empty. This is conservative and acceptable.
- **F6 against the old code.** In step 5 the clone stays on the plate and a Ki hit lands during the open window. In c2ccdae `cloneSeenAt` was refreshed every tick, so at `openUntil` the gate would reopen in the same tick and `State` would never read "closed" inside the 10 s wait. `closedAgain` would be false. The later Ki hit with the same clone would also reopen the gate, so `noReopenWithSameClone` would be false too. The scenario therefore exercises the exploit path and would have failed on the old code. The executor did not run it against the old code ([[TEST-20261010-09]] says so), so this is reasoning, not a run.
