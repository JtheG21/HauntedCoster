## Specific checks
- **Lazy `require` of CaptureService (`LandmarkService.luau:136`):** valid. CaptureService requires LandmarkService at load (`CaptureService.luau:27`), so a top-level require would be circular. By the time the 0.25 s loop reaches an ejection, both modules are loaded, so the lazy require returns the cached module with no deadlock. Cost: `:: any` removes type checking on `noteTeleport` (N3).
- **Positive controls restore gate state:** yes on the normal path (`Reachability.luau:103-120` saves `CanCollide` for both gates, then restores both and waits 1 s). It is not exception-safe, and there is no `pcall` or `finally` (N4). The controls change only server-side `CanCollide`, which is where the server pathfinder reads it. The client's local `CanCollide` changes (`LocalWorld.luau:125`) don't affect it. The scenario moves no player, so the crypt eject loop can't misfire. The controls do make the closed checks meaningful: Crypt `NoPath` while sealed, then `Success` open (the target is therefore valid), and the shortcut goes from 45 waypoints closed to 6 open. Stuck pockets are still not tested (stated by the executor).
- **DPadDown conflicts:** none found in `src`. The only gamepad bindings are DPadLeft/DPadRight in `TrackEditor.luau:350-372`. TEST-05 says the virtual gamepad toggled the light via DPadDown, which shows `InputBegan` delivery with `processed == false`. No physical controller was used, and I can't verify that Roblox reserves nothing on DPadDown on real hardware or console.
- **AC2 evidence sufficiency:** in code, the flashlight is a SpotLight with no battery, toggled by F, DPadDown and a HUD button. Screenshots now exist. They show the light helps and that off is dark. They also show that **ground paths outside the beam are not readable**, which the executor itself says. Whether that satisfies "paths and obstacles readable in the dark" is a design judgement the auditor can't make for the human.
