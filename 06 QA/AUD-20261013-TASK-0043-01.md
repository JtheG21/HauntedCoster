# Audit: TASK-0043 Creature Models and Animation (attempt 1)

## Verdict
**Pass**, with one major performance finding (1) that should be fixed before merge but is not a correctness or security defect. Server authority is intact: `MonsterModels` keeps the anchored Root (prompts still parent to it, `EncounterService.luau:196`), adds a welded massless non-colliding Hitbox, and the lights; `ContainmentService` only adds two attributes; `CaptureService.makeCage` keeps every physics flag (CanCollide/CanTouch/CanQuery false, Massless, Weld) and only swaps the visual (Transparency 1, art tags and attributes). No new remotes. `lune run scripts/lune/specs`: 143 passed, 0 failed. `validate_vault.py`: 0 errors. Commit 4893a4c (TASK-0042 audit fixes) reviewed lightly: bake timeout, pcall guards and the ServerStorage move look sound.

## Findings
1. **major** (performance, AC4) `Creatures.luau:82-89,159-171`: Spectral shell clones are not in `built.lod0`, so `record` puts them in both the near and far sets. From the exported `Tris` data: a Spectral creature draws LOD0 plus shells near (Hound 14.3k, Gentleman 10.5k, Wraith 9.9k, Wisp 6.2k against the 8.5k budget), and far away it draws the full-resolution shells (Hound about 6.1k) instead of the 1.1k LOD1. Fix: have `variantPart` return the shell and `applyVariant` insert it into `built.lod0` (near only), or tag it `Shell` and exclude it from `far` in `record`; then add a spec or capture of a far Spectral Hound.
2. **minor** `Creatures.luau:370-427`: `step` has no guard, so any error in `pose`/`BulkMoveTo` repeats every frame (RenderStepped never disconnects). None found. Fix: pcall per rig, disable that rig and warn once. Per-frame cost is otherwise fine (module-level arrays reused, one `BulkMoveTo` with `FireCFrameChanged`, far rigs at quarter rate beyond 140 studs, at most 25 parts per rig), but `pose` allocates a closure per rig per frame (262-364) and BellWraith runs `string.sub` on every part every frame (347); precompute a motion kind per `PartRec` in `record`.
3. **minor** `Creatures.luau:195-196,378-381`: `attach` yields in `ArtLoader.build` but never rechecks `rigs[host]` afterwards, and `step` removes stale rigs only through `detach(rig.host)`, which returns early when `rigs[host]` is nil or another rig, leaving a rig in `list` forever. Current paths do not double-attach (connect and `GetTagged` run without yielding), so this is latent. Fix: recheck after build; in `step` do `table.remove(list, i)` and destroy directly.
4. **minor** `Creatures.luau:183-187`: a 10 s `WaitForChild("Root")` timeout returns silently and never retries, so a slow replication leaves a creature invisible with no log. Fix: warn, or retry when `PrimaryPart` appears.
5. **minor** `Creatures.luau:396-410`: LOD swap has no hysteresis (a creature near `lodDistance` re-parents up to 25 parts per frame) and uses `table.find` in the loop; the `tick % 4` throttle starts at 0 for every rig so far rigs all update on the same frame. Fix: swap at 0.95/1.05 of `lodDistance`; stagger with the list index.
6. **minor** `Creatures.luau:387-389`: speed is flat distance over `dt` per frame from a server-tweened anchored Root, which updates at network rate, with a 30 studs/s clamp. Bursty steps can read low or jittery in chases and retaliation, and walk phase, the jaw snap (`speed > 10`) and the carried pose all depend on it. Unproven in motion (see AC3). Fix: smooth over at least 0.1 s or update only when the position changed, and judge a recorded clip.
7. **minor** `Creatures.luau:301-314` with `creatures.py:271-281`: joints are flat, not parented. The Wisp Lamp hangs at ArmL's end but animates on its own pivot, so the hand and lamp separate by roughly 0.15 studs; Hound Jaw and Head yaw about different pivots. Fix: let a part inherit its parent's motion, or reuse ArmL's motion for the Lamp.
8. **minor** `init.client.luau:46-55`: `Dressing.start` and `Creatures.start` share one pcall, so a Dressing error means creatures never start. Fix: two pcalls.
9. **minor** `ArtShowcase.luau:40-75`: Studio-only by construction (reachable only through `StudioTestHook`, which returns unless IsStudio, server and a `scenario` arg; no remote). But it writes `profile.coins`, `owned` and `exhibits` (lines 49, 61, 68) without checking `PlayerDataService.persistence(player) == "memory"`. "Studio places run memory-only" holds for an unpublished place, not a published one with Studio API access, where a tester's real profile would be changed and saved. Fix: return `{ ok = false }` unless persistence is "memory".
10. **nit** `MonsterModels.luau:43-58`: the Hitbox has no consumer (prompts use Root, the Highlight adorns the Model); header says "queries, prompts, highlights". Keep it with a corrected comment or drop it. Wisp light colour changed from blue to amber (visual only).
11. **nit** `Creatures.luau:448-457`: `applyVariant`, `count`, `jarOffset` have no callers or specs. `haunted.project.json:31-35` `Terrain.Decoration = true` came in with 372e40a and is recorded in neither task note.

## Refactor suggestions
- Make `record` pure (inputs: parts, lod lists, shells; outputs: near/far) and move it with `pose` tables to a module that lune specs can load; add a spec that no Spectral far set contains a LOD0 mesh.
- Replace the per-species `pose` branches with data (`part -> axis, amplitude, frequency, parent`) so hierarchy, skipping and the per-part kind come for free.
- Share the LOD swap (with hysteresis) with `client/Art/Lod.luau` rather than a second implementation.
