### TrainService handover trace
- `rebuild` while `riding` sets `old.rebuildPending` (`TrainService.luau:203-205`). The pending rebuild runs at `:490-497`, **before** the `if cancelled` return at `:499`, so it applies after both cancelled and completed rides.
- `:486` (`riding = false`) to `:496` (`rebuild`) does not yield, so no new ride or `SubmitRoute` can slip in between. During the ride, `ride` (`:412`) and `SubmitRoute` (`:563`) both refuse.
- `rebuild` replaces `trains[index]`, while the ride function keeps using the old `t` for the payout (`:515`). That is safe: the only ways to set `rebuildPending` mid-ride are an owner change (the owner leaving, so `player.Parent` is nil and the ride is cancelled with no payout) or `onAssigned` for a new owner. A route change is refused while riding. So the old route is only ever paid to the player who rode it, and the new owner can't ride or be paid on the old track: their first ride uses the rebuilt `trains[index]`.
- The owner is re-read at the end (`:494`), so a release followed by a new assignment during the same ride builds the latest owner's route.
