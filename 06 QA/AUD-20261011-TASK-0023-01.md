## Evidence
- **`scripts/check.sh`:** ALL CHECKS PASSED (vault 0 errors / 45 pre-existing warnings, Python 32 tests OK). Luau specs and gameplay need Studio.
- **Grab surface (`CaptureService.luau:192-204, 384-406`):** the prompt calls `grab(who)`, which looks up `chases[who]`, so only a player with their own chase can succeed, and the distance is measured to **their own** runner (6 + 2 studs, flat). A non-owner without a chase gets `false`; a non-owner with their own chase who triggers someone else's prompt can only grab their own runner, and only from within 8 studs of it. Deadline (`os.clock() >= ch.deadline`), dead/no character, and already-carrying are rejected. Double grab: `endChase` clears `chases[player]` before `startCarry`, so a second trigger returns `false`. Once per capture: `startCarry(..., true)` sets `chased = true`, and `escape` skips the chase when `c.chased` (`:220`). The distance uses the client-owned root, so a teleport exploiter can reach the runner, the same limit as `START_DISTANCE`; the regrab carry is then speed-checked.
- **Startle and `claimEpoch` (`EncounterService.luau:277-287, 320-343`; `CaptureService.luau:104-118, 438-440, 527-531`):** a miss ends the session as `startled`, stores the counters and keeps the claim. `isStartled` blocks every start for 0.8 s; the delayed release clears the claim only if the claimer and epoch are unchanged. A same-player restart bumps the epoch (no stale release); another player hits "Someone else is capturing it" for at most a frame; a leave clears the claim via `PlayerRemoving`. No race found that drops a live session's claim.
- **Progress carry-over:** counters are per player on the encounter, saved on cancel/timeout/startle/death, dropped on success/fled (encounter removed) and on leave. Hits only rise through a judged hit, so they cannot be farmed; misses can only be reset by leaving the server (rejoin cost). Cancel and timeout no longer cost hits, but the needle is deterministic, so this gives no real advantage.
- **Chase lifecycle:** timer expiry on a living player → chase (`:211-232`); death during a carry → `lose` (Died handler passes no `canChase`); death or missing humanoid during a chase → `endChase("You fell!")` within 0.25 s (`:680-687`); leave → runner removed, `respawnEscaped` (`:713-720`); regrab then speed strikes → `lose`. Coins and `owned` are never written on these paths.
- **Spawn caps:** `clearCarry` (−1 carried) then `spawnFleeing` (+1 alive) run without a yield, so `maxAlive` totals are unchanged; the runner counts toward its habitat's zone cap during the chase; `respawnEscaped` re-checks both caps. No duplication path found.
- **Speed check after regrab:** `startCarry` resets `lastPos = nil` (`:345`), and `walkSpeed` uses `carryMultiplier`, so the server check and `MovementService` share the rule (AC3). At level 0 the allowance is 9.6 × 0.25 × 1.35 + 2 = 5.2 studs per tick.
- **Client trust:** `snap.chase` is server → client; `Hud.luau` type-checks `monster` (`typeof`, `IsA("Model")`, `PrimaryPart`). The client never sends chase data back. OK.
- **Tests:** the new FullLoop checks discriminate: removing `isStartled` fails "no instant retry", removing the session end fails "a miss ends the meter session", dropping carry-over fails "retry after the hop keeps the miss" (`FullLoop.luau:379`), removing the distance check fails "grab from too far rejected" (`:411`), and removing `chased` fails "second timeout sends it home" (`:422`). The ExploitProbe mash check (`counted == 1`) follows the new rule. Gaps are listed in F4.
- **GDD v0.3 / Overview:** both record Q1 to Q5 and the hook (AC5). GDD says the runner "stays on its side of the graveyard fence", which F2 contradicts for the crypt.
