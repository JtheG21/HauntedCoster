### First-registration tier

The first-registration limitation should block merge. A PR that adds its task JSON also chooses the tier in the commit that the gate treats as authoritative. It can declare light while changing security code or CI, and the gate returns success before looking for an audit. A human plan approval can catch a misclassification during manual review, but the gate has no trusted record of that approval and cannot enforce the independent audit policy when the registration and implementation arrive on the same branch. The audit requirement needs a registration approved outside the PR or a fail-closed rule for new source-bearing registrations.
