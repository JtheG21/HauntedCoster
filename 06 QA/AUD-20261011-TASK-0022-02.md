## Evidence
- **`bash scripts/check.sh`:** ALL CHECKS PASSED (Python 32 tests OK; Luau specs and gameplay need Studio).
- **Exact `judge`, by reading:** the needle is a triangle wave with troughs at `kP` and peaks at `P/2 + kP`. A peak lies in `[a, b]` iff `floor((b-P/2)/P) >= ceil((a-P/2)/P)`, and a trough iff `floor(b/P) >= ceil(a/P)`. Both are correct, including a window that contains a peak, a trough or both (then lo=0, hi=1) and a peak or trough exactly on an edge (floor and ceil are equal there). Luau `%` is a floor modulo, so negative times work. `period <= 0` skips the branches and `needle` returns 0. The needle is continuous, so its range over the window is `[lo, hi]` with no gaps, and the zone test is an interval overlap. Outside peaks and troughs the covered width is `width + 2*slack*(2/period)`, i.e. exactly `judgedWidth`. A window with a peak or trough covers less than `judgedWidth` near the bar ends, which is safe (the drawn zone is never narrower than what is judged anywhere the zone can sit, given the 0.08 margin).
- **Difficulty change:** the server (`CaptureService.luau:354`) gets the exact window. The old 5 ms scan missed up to about 0.007 of bar width, so the judge is now very slightly more forgiving, but it now equals the drawn zone, which was the point of F4. No other relaxation: the same `slack`, and `MinReleaseGap` and the miss counters are untouched. The mash-rate spec (`CaptureRules.spec.luau:79-88`) keeps its intent (blind presses on a window that is at most 0.01 wider); I could not run it, so the executor's pass is a claim.
- **Capture spec tolerance:** the measurement samples at `period/4000`, so it undershoots by at most about 0.001; the 0.002 tolerance holds against an exact judge and fails if `judgedWidth` is dropped (Rare error about 0.16).
- **Cumulative roll:** one draw `r` against a running sum over the variants allowed in the zone gives each allowed variant exactly its `chance` (Crypt: Spectral 10%, Ashen 30%, Normal 60%; elsewhere Spectral 10%). The new spec checks Crypt Spectral at 0.1 within 0.015 (sd about 0.003 at n=10000), so the old 7% would fail it. If allowed chances summed past 1, the later variants would be truncated silently (see N4); today the Crypt sum is 0.4.
- **`slotsInRange`:** cost is small: at most 16 points, about length/3 sampled points, at most 4 slots, one `validate` plus one `sample`, run per snapshot push, and pushes are throttled to 0.25 s and only when dirty (`StateService.luau:12,87`). It uses the same `routeFor`, `sample`, `nearestDistance` and `ExhibitRange` as the payout, so it fixes F3. One divergence: during a pending rebuild the pay uses the old `trains[i].sampled` while the flags use the current profile route; that only happens at a handover, and the new owner's first ride is on the rebuilt track. One side effect: `routeFor` warns on every call for an invalid saved route, so it now warns on every snapshot (N1).
- **FullLoop handover block (`FullLoop.luau:364-406`):** it exercises the pending path. It uses the current character and humanoid (read after the respawn block), teleports, starts a real ride and checks the seat is `FrontSeat`. It then mutates `profile.route` and calls `rebuildForOwner` mid-ride. The first check (rails unchanged while riding) can only pass if `rebuild` deferred, because the starter loop gives a different rail count; the second (rails differ after the cancel) can only pass if the pending rebuild ran at ride end, through the cancelled branch (`TrainService.luau:510-513` runs before the `cancelled` return). Only the cancelled-ride exit is covered; the completed-ride exit shares the same code. The route is restored and rebuilt afterwards. It assumes `PlayerDataService.get` returns the same table as `profile`.
- **Editor retry (`TrackEditor.luau:429-434`):** it re-arms only while `editing` is true and `controls` is still nil, so it stops on close or once `PlayerModule` loads; it cannot run forever after the editor closes. Each reopen while the module is still missing can start a second chain; chains die at their next tick after close. It is bounded and cheap (N3).
- **Deferral record:** the task note (Revision 1, F1) and TEST-07 quote jg's chat answer ("Clear it, skip CrossPlot") dated 2026-10-11 and name the TASK-0020 session as the place to run it. TASK-0020's **In** scope now lists "A 2-player CrossPlot run ... deferred from TASK-0022 by jg". Properly recorded. AC3 text itself was not amended (N5).
