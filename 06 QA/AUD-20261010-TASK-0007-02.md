### Revision mechanisms checked
- **`concluded` freeze (`FinaleService.luau:133-153`).** Every path that can end the finale calls `checkConcluded`: the poll after a batch (`:174`), a respawn elimination (`:243`), `PlayerRemoving` (`:364`) and the time limit (through `isOver`, `:231-234`, which `MatchService.tick` calls every 0.2 s in the Finale state). After `conclude`, `poll` returns early (`:156`), `respawn` doesn't eliminate (`:238`), and `isAlive` is false (`:228`), which blocks `knockback`, `grantGuard`, `canSpend` (so `EchoBurst`/`EchoGuard` fail eligibility in `AbilityService` before a charge is spent) and the Ki Burst/Echo Clone hooks. `begin` (`:194`) and `reset` (`:330`) clear the flag. The attempt-1 F1 scenario (two falls 0.1 s apart) now gives survivors `{A}` from the frozen table, so A wins. One leak remains: `PlayerRemoving` still edits `alive` after conclusion (finding 1).
- **`ResultRules.combat(survivors, lastOut, starters)` (`ResultRules.luau:37-48`).** Correct for its inputs and the five specs cover 1 survivor, a simultaneous pair, a time-limit draw, solo fall and the new 2-starter single last-out case. Note: with the freeze in place, the new `#survivors == 0 and #lastOut == 1` branch is no longer what fixes F1. It is reachable only when the survivor leaves (finding 1).
- **`StartGraceSeconds = 1.0` (`FinaleService.luau:156`).** It can't be abused to linger: it only delays the poll. Knockback works during the grace, and a player knocked off is still caught at t ≥ 1.0 s (below y=40 after a 0.45 s fall) or on respawn (`respawn` isn't gated). The time limit and leaves still conclude through `isOver` and `PlayerRemoving`. The weakness is the other direction: it's a fixed guess (finding 3).
- **Server-simulated knockback (`FinaleModifiers.luau:25-53`).** The token logic is sound: `ServerOwnSeconds` is constant, so an older callback always fires before a newer one and the counter only resets when the latest callback runs. No stale hand-back can cut a newer push short. If the target leaves, `target.Parent` is nil and the entry is cleared at the next callback. If the character is replaced during the window, the old root is unparented (or on a dead body) and the new character gets default ownership. An eliminated target is teleported by the server (`toSpectate`) while it owns the root, which is fine. The attacker's assembly is never touched. Ownership can stay with the server only if the hand-back `pcall` fails silently (finding 5). A client can still teleport back after reclaiming ownership at 0.6 s, so attempt-1 F3(a) is only partly addressed.
- **Dead players excluded from starters (`FinaleService.luau:202-210`).** They get `alive=false` and `FinaleAlive=false`, aren't counted or teleported, and a later respawn sends them to spectate (`:244-245`). With every player dead, `finaleOver(0, 0, ...)` concludes on the first `isOver` and Results shows "nobody survived". Edge in finding 6.
- **`ConvergenceGate.onContribution` listener list (`ConvergenceGate.luau:160-162, 232-240`).** Works, and the scenario now disconnects its listener, so the game's Teamwork listener stays in place. Small iteration caveat in finding 7.
