## Evidence
- **Files and diff reviewed:** listed above.
- **Automated checks (re-run by the auditor):** `bash scripts/check.sh` gave **ALL CHECKS PASSED**.
- **Studio (executor claims):**
  - [[TEST-20261011-03]]: a real client went from capture to secure in 52 s of the 75 s timer. WalkSpeed went 16 → 11.2, and the +60 first-catch bonus was paid.
  - [[TEST-20261011-04]]: FullLoop 56/56 and CrossPlot 12/12 with 2 players. The first CrossPlot attempt failed because the second client never joined (a harness problem), and the re-run passed.
- **Scenario code checked:**
  - CrossPlot uses two real players. B secures first. A then captures, is moved onto B's pad and calls `secure(a, ib)`. The check confirms that A owns nothing and is still carrying, and that B's roster is unchanged. A then secures at their own pad (`CrossPlot.luau:104-129`).
  - The scenario calls `secure` directly instead of firing the prompt. In the game, each pad's prompt is bound to its own plot index (`CaptureService.luau:460-476`), so a client can't choose the index.
  - The FullLoop timeout case goes through the real deadline loop via `expireCarryForTest` and checks both owned monsters and coins (`FullLoop.luau:337-352`).
- **Races (re-checked):**
  - Secure and escape both still go through `clearCarry` with no yield first, so a monster can't be secured twice or escape twice.
  - The new speed check runs inside the same loop as the deadline check (`CaptureService.luau:497-503`). When `escape` nils the current key during iteration, that is safe in Luau.

## Findings
| # | Severity | Location | Evidence | Required correction |
|---|---|---|---|---|
| 1 | minor | `server/Services/CaptureService.luau:132-159, 377-391` | The new speed check allows `walkSpeed × 1.35 + 2 studs per tick`, which is about 23 studs/s at level 0 while carrying (11.2 base). Running unslowed at 16 studs/s is never flagged, so it doesn't stop the exploit it was written for. Strikes go down by one on each clean tick, so speeding on alternate ticks never reaches 3. A single client-side teleport to the pen is one strike, so it isn't caught, and `secure` doesn't check that the trip home was plausible. Acceptable for an unpublished prototype. | Before public play: <ul><li>use a cumulative distance budget, not per-tick strikes;</li><li>escape immediately on a single jump over N studs (call `noteTeleport` for server moves);</li><li>in `secure`, reject a carry whose elapsed time is shorter than the capture-point-to-pen distance divided by the allowed speed.</li></ul> |
| 2 | minor | `server/Services/EncounterService.luau:290-302`; `shared/Config/World.luau:97-112` | `respawnEscaped` puts the monster in the first zone, in `World.Zones` order, that has its species and room. An escaped Crypt **Ashen Gentleman** therefore lands in the Hollow (not gated) whenever the Hollow has a free slot. That breaks ADR-0006 ("Ashen … Sealed Crypt only"), and a player without crypt access can catch it. If every zone is full, the escaped monster disappears instead of "returning to the graveyard" (ADR-0005), and it comes back only as a fresh roll. | Respawn in the zone it was captured from (store `zone` in the carry), or strip zone-restricted variants when placing it elsewhere. Decide whether an escape may exceed the zone cap, and record that. Add a spec or scenario case. |
| 3 | nit | `CaptureService.luau:135-159`; `LandmarkService.luau:135`; `TrainService.luau:139` | Server moves that don't call `noteTeleport` (the crypt ejection, the cart re-park with a seated rider) and network stalls each give a false strike. One alone can't drop the capture, but a laggy player could collect several. Not validated on a live server. | Call `noteTeleport` from every server-side character move. Check the tolerance on a live server with real latency. |
| 4 | nit | `tests/scenarios/FullLoop.luau:295-310` | The death-while-carrying case still doesn't snapshot coins. Only the timeout case does. | Add the coin snapshot to the death case. |
| 5 | nit | `CaptureService.luau:377-399` (carried from attempt-1 F6) | `secure` doesn't check `c.deadline`, so a secure up to 0.25 s after the timer runs out succeeds. | In `secure`, escape if `os.clock() >= c.deadline`. |
| 6 | nit | Task note; `tasks/queue.json` | The Implementation record is stale (it says FullLoop hasn't run). Planned file names differ. The queue shows TASK-0014 as `ready`. | Update the note. Reconcile through the orchestrator. |
