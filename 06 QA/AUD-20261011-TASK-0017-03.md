## Evidence
- **`bash scripts/check.sh` (run by the auditor):** **ALL CHECKS PASSED**. Vault: 0 errors, 45 warnings (ambiguous links in GAME-001 notes, unrelated). Python: 32 tests OK. Luau specs and gameplay need Studio.
- **Thin-loop spec traced** against `validate`'s order of checks:
  - Control points `thinLoop(3)` are (-8,-36), (38,-36), (44,-34.5), (38,-33), (-8,-33), (-14,-34.5).
  - Nearest control-point spacing is 6.18 (at the ends) or 46 (on the sides), so "Two points are too close together" (`TrackRules.luau:136`) doesn't fire.
  - Every point is inside the bounds (x -18..46, z -40..12).
  - The length is about 121 studs (60..320 passes).
  - The sampled curve spans x -14.4..44.4 and z -36.2..-32.8, inside bounds plus the 3-stud margin.
  - There are no crossings. Catmull-Rom bows the two long sides apart, so they don't meet.
  - The minimum segment distance is **2.66**, between segments 14 and 17 (more than `skip = 3` apart), so only the clearance rule (`:198-208`) rejects it. The spec asserts the exact reason, so it can no longer pass for the wrong reason.
  - Positive cases: gap 8 gives a minimum of 4.92, and gap 6 gives 4.79, so both are valid. The starter route's minimum is 6.12.
  - The spec reaches the rule, and the rule has real margin on the valid side.
- **`segSegDist` (`:103-105`):** for non-crossing segments the minimum distance is attained at an endpoint, so the minimum of the four point-to-segment distances is exact.
  - Crossings are rejected earlier for every pair with `j >= i+2`, which is a superset of the pairs the clearance loop visits (`j >= i+3`).
  - Collinear or touching pairs are not caught by `segmentsCross` (it requires all four orientations to be non-zero). `segSegDist` gives about 0 for them, so clearance rejects them.
  - Zero-length segments are handled (`len2 > 0`).
  - The bounds `j - i >= skip` and `m - (j - i) > skip` are slightly asymmetric across the wrap, but only by one segment, and it's harmless.
- **`isSequence` (`:80-89`):** correct for these cases.
  - A hole is caught whether `#` returns the border below or above it: either a key is greater than n, or the count is smaller than n.
  - A float, negative, string or boolean key returns false. `n = 0` is only reached for pieces (an empty table passes).
  - `n` is capped before it runs, and it exits on the first bad key. NaN can't be a table key.
  - Both `points` and `pieces` are covered.
  - The spec asserts `Bad point` for the extra-key case and `ok == false` for holes.
- **Controls disable/enable (`TrackEditor.luau:407-420`):** `setMovement(false)` runs in `open` (`:483`) and `setMovement(true)` in `close` (`:430`). Every close path goes through `close()`: Exit, B, a successful Confirm, `CharacterRemoving` (`:593`), ride start and the HUD toggle (`init.client.luau:60`, `:80`). The `editing` guard stops double calls. See F4 for the remaining edge.
- **ExploitProbe route check:**
  - It now unlocks tier 1 through `EconomyService.purchase`, so the unlock gate (`TrainService.luau:549`) passes.
  - It asserts exact reasons: 10000 points gives `At most 16 points`, a NaN point gives `Bad point`, and `"x"` gives `No route`. The rate limit's "Slow down" and the unlock message would both fail that equality, so the check can't pass for the wrong reason.
  - `profile.route == nil` at the end shows nothing was stored.
  - The shortcut doesn't mask a route defect (see F3 for a small side effect).
- **Rate-limit spacing:** the `SubmitRoute` bucket is `rate 0.5/s, burst 2` (`TrainService.luau:541`, `Remotes.lua:68-87`). It starts with 2 tokens, so the first call is free. After a 2.5 s wait the next has 1.25 tokens regained, so each call is admitted. The 2.5 s spacing is sufficient and a little conservative.
